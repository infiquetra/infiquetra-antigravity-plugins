# Impl-Spec Author Assignment

Use this template for one folder assignment. Replace every bracketed field before dispatch. The
assignment is a document-authoring contract, not permission for code, Git, GitHub, or deployment
mutation.

## Identity

- Profile: `[profile-id]`
- Folder: `[folder]`
- Wave: `[wave-number]`
- Required files: `[repository-relative file list]`
- Staging workspace: `[ignored mirrored workspace root]`
- Completeness rule: `[verbatim README rule]`
- Dependency inputs: `[accepted earlier-wave artifact references]`
- Execution identity: `[unique receipt-bound id]`

## Inputs

Read only:

- the accepted grounding brief;
- upstream requirements and cited repository evidence;
- the folder contract row;
- accepted earlier-wave specifications named above;
- shared formatting, lifecycle-closure, and project standards.

Do not read another author's hidden reasoning, private transcript, prior probe artifact, or remediation
notes.

## Deliverable

Write only the assigned files beneath the staging workspace. Preserve their canonical
repository-relative paths inside that mirror. Every externally visible behavior, entity, endpoint, field,
enum, error, event, ownership boundary, and failure mode must be explicit. When stateful entities are
present, complete every lifecycle-closure cell. Reference cross-record rules from one canonical
source. Synchronize contract and prose both directions.

Return:

- changed staging paths;
- satisfied completeness clauses;
- named dependency evidence;
- unresolved questions with product-visible impact;
- mechanical checks performed;
- the execution identity and receipt reference.

## Stop conditions

Stop without inventing content when the folder contract, grounding decision, dependency, or
capability receipt is missing. Never write directly to canonical `docs/specs/`; promotion owns that
mutation. Do not commit, push, open a PR, mutate an issue or board, merge, deploy, or claim phase
completion.
